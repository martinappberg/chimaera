# First-party application presentation boundary

The official app composes one optional extension: the account, Settings, Home and cloud presentation, the kept-review pane, and the place and host slots. The trusted build exports either one literal installed-entry facade or null (`virtual:chimaera-application-entry`, written by `web-ui/scripts/application-entry.mjs`); there is no runtime URL selector, no new account client and no authority beyond the fixed callbacks below. The trusted assembly gives each window one exact runtime service object and an already-selected module. A null build loads no private code and makes no account, kept-review or modal subscription. Installation, signature and entitlement checks live elsewhere.

## Invariants

- **Mutable services stay in the host.** Account, kept-review, onboarding, route/token/socket and modal services are never copied into a separately bundled UI. Callbacks keep the exact original instance; an independent presentation runtime may copy only types and pure formatting. The emitted private bundle is checked to reject copied host implementation modules and external runtime imports; `application-entry.mjs` captures the bounded input graph and writes no receipt into the bundle (nothing read one, and it carried the build machine's paths).
- **Narrow surface.** No generic invoke/fetch/token/URL getter, no second modal stack, no plugin-WIT change. The caller supplies `modalFocus` at ordinary priority, and its node must belong to the current attempt target; host retirement destroys every tracked modal handle before disposing presentation. Presentation and identity projections copy only declared fields, so structural extras never reach the private entry.
- **Mount lifecycle.** Each pending mount owns an isolated child target. Retire or detach synchronously before a successor; a late owner is disposed against its own child, even when disposal throws. A window holds at most eight pending mounts; a mount closes after ten seconds and Retry stays explicit and bounded. Explicit Cancel closes only the still-current captured surface and always cleans up presentation; retirement cleanup alone never closes a successor. Original pane callbacks and the full onboarding provider/workspace identity stay captured. File actions use bounded POSIX-relative paths (a backslash is a legitimate filename character).
- **One selection.** `KeptApplicationView`, the account surfaces and branding share the one module-level `selectedApplication`; the null check precedes building a facade, which keeps one shared module load. Branding exposes one subscription method with closed environment fields and the subscriber's signal; its first gateway lookup carries one absolute ten-second deadline through module admission and lookup, an expired deadline refuses before loading the entry, and later refreshes keep their own ten-second budgets. Late registration is disposed; the facade and the public store both stop publishing after abort.
- **Account.** Every selected account port captures the exact 64-hex account lifetime before exposing services, and fixed native commands and browser routes carry that receipt. A normal refresh keeps the port; retirement invalidates its host revision synchronously and starts a new read. Only native proof of the original successful Sign in preserves a setup draft, and it grants no mutation authority. Settings imports the account component on demand, so its runtime never enters the default entry. Setup decisions use the original native operation owner with the shown command capped at 16 KiB; browser decisions keep the original lifetime header and recheck after each await. The host session owns and disposes the exact account port, counts late factories against the original mount deadline and never builds one for a null assembly; native status without a receipt refuses admission, and a mounted original keeps its receipt and draft without adopting or replaying anything.
- **Kept review.** Domains exist only for an explicitly supplied kept-review host factory, captured to the original surface and disposed on every retirement or failure. There is no new wire route or server compare-and-swap: a client revision refuses stale presentation intent, and the daemon's own project, ownership and path checks still decide. Mutations run once with no replay; a lost reply triggers only an ordinary read. File reads hold two slots until they settle, even after abort, and metadata must still match the displayed pair. Eight listeners or confirmations bound each domain; a malformed update becomes a fixed unavailable state. An empty listed or unnamed Done carries a one-use keep-both acknowledgment and keeps the copies; an empty destructive choice refuses. A deliberate refresh always creates a fresh read revision and never replays a choice. Observed auth retirement and a validated placement owner change retire captured intent; owned↔suspended renewal of the same workspace/epoch/holder/route does not. A new domain refuses its predecessor's cache until a guarded listing succeeds, and a different owner refuses busy rather than adopting an older request.
- **Focus across keep-alive.** `../shared/modalFocus.ts` keeps the last focused descendant while a keep-alive layer is inert; one inert-attribute observer restores it only when a related layer changes and the highest-priority owner needs focus, and disconnects after the last disposal.
- These are client intent fences, not server authority or proof of unseen browser cookie changes. The tests here (`*.test.ts`, with `../shared/modalFocus.test.ts`) drive controlled owners; they are not authenticated daemon, installation or entitlement acceptance.
