# Client transport map

The public UI runs directly on a daemon, inside the native shell, or beneath a browser gateway path. Read [the transport contract](../../../../crates/chimaera-link/PROTOCOL.md) before changing gateway behavior.

| File | Responsibility |
|---|---|
| `base.ts` | derive the immutable per-tab `/app/{host}` prefix and construct daemon HTTP/WebSocket URLs; `isAccountHome` recognizes the account's own signed-in page at `/` by its `chimaera-surface` marker (no daemon behind it: `main.ts` mounts `pro/AccountHome.svelte`, and `plan.ts` reads its plan with the same `HEAD`) |
| `api.ts` | authentication bootstrap, typed HTTP wrapper, browser CSRF marker, reauthentication signal; `ApiError` turns the daemon's project-connection codes (`project_unavailable`, `workspace_owned_elsewhere`, `remote_unavailable`, `workspace_scope_changed`, `read_only`, `worker_asleep`, `on_other_machine`) into plain sentences and keeps the code on `.code`; `projectStateNote` reads a project's *state* (`worker_asleep`, `project_unavailable`, the reconnecting codes) as a quiet line — "Asleep in the cloud. Send a message to wake it." — that a surface shows in its muted voice, never as an error; "running elsewhere" names the cloud or your computer from the daemon that refused (`ownerElsewhere`: this computer's daemon hands projects to the cloud, the cloud's hands them home; a project view cannot tell and says "somewhere else") |
| `reconnect.ts` | the shared reconnect backoff (`Reconnector`, nudges, the hidden slow tier), `QUIET_OPEN_MS` (a chat/terminal socket that authenticated and heard nothing for 1.5 s counts as kept open for an owner that has not answered: healthy, off the reconnecting indicator; a browser cannot read a keeper's `X-Chimaera-Sockets: kept` mark, so silence is the signal) and the wait for a sleeping owner: `parkUntilAwake` (sockets) and `refetchWhenOwnerAwake` (a panel that met a project state re-reads once the project answers again — `ownerAwake`, which a placement read, a project view's events socket and any chat/terminal socket `ready` all raise — visible-only; `pollMs` adds one slow recheck for a state nothing announces the end of, like a project routed elsewhere that came home) |
| `events.ts` | daemon event stream and reconnect lifecycle; `remote_unavailable`/`workspace_scope_changed`/`worker_asleep` mean "reconnect", only other errors are fatal; an open socket that says nothing is healthy (no silence timer), and in a gateway view every `settings` frame re-sends the `watch` registration, because a keeper that keeps a sleeping machine's socket attaches it afresh after each sleep |
| `placement.ts` | browser-view placement reads (`owned` and `suspended` both route; `ownerSuspended` for the socket wait), scoped socket auth, `placementLabel` ("In the cloud" / "On another computer" / "· reconnecting", or "· asleep" / "· waking" once the view's socket heard so — a sleeping owner fails the roster read like an unreachable one) for routed rows, `projectWhere`/`projectWhereLabel` (a project view's strip and Home heading: "In the cloud" / "On your computer" from the latest placement read), and `parsePause`/`sessionPause`/`pauseLabel`: a session's `moved`/`paused` state (socket frame or the row's additive `pause`) in plain words (`movedTo`: a `moved` with the additive `other:true` is another of the user's computers, "Continuing on your other computer…") |
| `native.ts` | native IPC with browser fallbacks and prefixed window URLs |
| `proReturn.ts` | targeted account-return listener: register before consuming the native pending-window marker, coalesce events, and ignore late results after teardown |

Viewing a project that runs elsewhere is passive: sockets attach without `wake=interaction`, and only a user action carries wake intent. A `suspended` placement (a sleeping cloud machine keeping ownership) is routed exactly like `owned`. A keeper may keep a sleeping cloud machine's sockets open (it marks them `X-Chimaera-Sockets: kept`; [VIEWING.md](../../../../crates/chimaera-link/VIEWING.md), "A sleeping cloud machine's sockets"; none is deployed as this is written). Against one, a socket opens as usual, stays open and quiet, a send or keystroke on it is simply sent (the keeper holds it, wakes the machine and delivers it once), and a later `ready` on the same socket is a reattach (chat: only the gap, no reset; terminal: like a reconnect's, read against the auth frame with the `park`/`unpark` sent since folded in, `SessionSocket.wireParked`; a hidden terminal never sends a grid). `remote_unavailable` with `reason:"reconnecting"` is a relay retrying an unreachable owner (lasting, "Reconnecting…"); without it, it ends a wake on a socket that is still kept (quiet again is kept again). `placementLabel` takes `reachable` (the view's own socket is answered or kept) so a row whose roster read fails does not read "· reconnecting" then, and `ownerIsCloud` says whether a viewed conversation runs on a cloud machine. What follows is what happens against a keeper that refuses or closes those sockets, which is today's, and it is unchanged. A chat or terminal socket that was refused, or dropped while its owner is asleep (`worker_asleep`, or a project view's latest placement read says `suspended`) waits with no timer (`reconnect.ts` `parkUntilAwake`) instead of backing off: a send or keystroke dials it with wake intent, and `ownerAwake` (an owned placement read, a project view's events socket coming up) or the row becoming reachable (`retrySoon`) dials it passively. In a native window the daemon keeps the viewer socket open and holds the first input itself; in a browser view a send or keystroke into a dropped socket reconnects once with wake intent (never queued). Viewer chrome (terminal access strip, chat connection row) is gated on a routed row (`typeof session.placement === "object"`) or a browser view (`isBrowserGateway()`), so free users never see it. Viewport width matters only in an account-gateway browser view, and only as a starting default: at phone width (≤700 px) it starts terminals watching (`terminal/viewerMode.svelte.ts`) and opens its layout in focus mode (`App.svelte`). A plain daemon in a browser and a native window of any width keep the layout `main` gives them (free users see no change), and neither default is ever saved. The full contract is [VIEWING.md](../../../../crates/chimaera-link/VIEWING.md).

Never put browser credentials in JavaScript, storage, URLs or proxy pages. Gateway requests use an HttpOnly cookie and same-origin proof; account browser sessions are distinct from daemon bearer tokens. Host choice belongs to the URL, never a shared cookie. Keep direct/native URLs unchanged, and preserve nonsecret workspace/window bootstrap metadata when switching hosts. Arbitrary preview apps must run on their isolated preview origin; their opaque proxy ids are capabilities, never raw daemon tokens. No user-selected upstream origin is accepted by the gateway helper.

Checks: `npm --prefix web-ui run check`, targeted `base.test.ts`, and live shared-UI HTTP + terminal/event WebSocket verification through the gateway. A passing direct-daemon check alone does not exercise gateway prefixes.
