# Client transport map

The public UI runs directly on a daemon, inside the native shell, or beneath a browser gateway path. Read [the transport contract](../../../../crates/chimaera-link/PROTOCOL.md) before changing gateway behavior.

A browser logical-project view (`/workspace/{id}/`) has a **Home** link in the
existing rail header and focus-mode strip. It goes to the same-origin account
root `/`, including when the sidebar is hidden on a phone. It carries no daemon
path, host selection or wake intent; ordinary daemon and native windows have no
account Home link.

Viewing a project that runs elsewhere is passive: sockets attach without `wake=interaction`, and only a user action carries wake intent. A `suspended` placement (a sleeping cloud machine keeping ownership) is routed exactly like `owned`. A keeper may keep a sleeping cloud machine's sockets open (it marks them `X-Chimaera-Sockets: kept`; [VIEWING.md](../../../../crates/chimaera-link/VIEWING.md), "A sleeping cloud machine's sockets"; negotiated per connection). Against one, a socket opens as usual, stays open and quiet, a send or keystroke on it is simply sent (the keeper holds it, wakes the machine and delivers it once), and a later `ready` on the same socket is a reattach (chat: only the gap, no reset; terminal: like a reconnect's, read against the auth frame with the `park`/`unpark` sent since folded in, `SessionSocket.wireParked`; a hidden terminal never sends a grid). `remote_unavailable` with `reason:"reconnecting"` is a relay retrying an unreachable owner (lasting, "Reconnecting…"); without it, it ends a wake on a socket that is still kept (quiet again is kept again). `placementLabel` takes `reachable` (the view's own socket is answered or kept) so a row whose roster read fails does not read "· reconnecting" then, and `ownerIsCloud` says whether a viewed conversation runs on a cloud machine. The fallback below applies when a keeper refuses or closes those sockets without advertising that capability. A chat or terminal socket that was refused, or dropped while its owner is asleep (`worker_asleep`, or a project view's latest placement read says `suspended`) waits with no timer (`reconnect.ts` `parkUntilAwake`) instead of backing off: a send or keystroke dials it with wake intent, and `ownerAwake` (an owned placement read, a project view's events socket coming up) or the row becoming reachable (`retrySoon`) dials it passively. In a native window the daemon keeps the viewer socket open and holds the first input itself; in a browser view a send or keystroke into a dropped socket reconnects once with wake intent (never queued). Viewer chrome (terminal access strip, chat connection row) is gated on a routed row (`typeof session.placement === "object"`) or a browser view (`isBrowserGateway()`), so free users never see it. Viewport width matters only in an account-gateway browser view, and only as a starting default: at phone width (≤700 px) it starts terminals watching (`terminal/viewerMode.svelte.ts`) and opens its layout in focus mode (`App.svelte`). A plain daemon in a browser and a native window of any width keep the layout `main` gives them (free users see no change), and neither default is ever saved. The full contract is [VIEWING.md](../../../../crates/chimaera-link/VIEWING.md).

Never put browser credentials in JavaScript, storage, URLs or proxy pages. Gateway requests use an HttpOnly cookie and same-origin proof; account browser sessions are distinct from daemon bearer tokens. Host choice belongs to the URL, never a shared cookie. Keep direct/native URLs unchanged, and preserve nonsecret workspace/window bootstrap metadata when switching hosts. Arbitrary preview apps must run on their isolated preview origin; their opaque proxy ids are capabilities, never raw daemon tokens. No user-selected upstream origin is accepted by the gateway helper.

Checks: `npm --prefix web-ui run check`, targeted `base.test.ts`, and live shared-UI HTTP + terminal/event WebSocket verification through the gateway. A passing direct-daemon check alone does not exercise gateway prefixes.

Personal provider wrappers use separate `pro_personal_provider_*` IPCs with closed
original parent identity and one-shot command payloads. There is no daemon or
URL fallback; personal account transport selection belongs to the private optional account controller.

The optional kept adapter captures an opaque public API owner (no token or request method) and exact logical placement owner. Auth loss/recovery or a genuinely new bearer retires old intent; ordinary account refresh/event socket reconnect does not. A delayed old 401 cannot retire a recovered owner, and auth retirement invalidates pending placement publication/coalescing. Opt-in `ApiGuard` is checked before preparation, after the existing placement await, immediately before fetch and after reply; guarded kept JSON decoding also rechecks before delivery. Logical placement compares workspace/epoch/holder/route_host_id from the SAME row that fills headers; owned↔suspended renewal is unchanged. Default unguarded routes/headers are preserved. These guards are client intent fences, not new wire authority or proof of unseen browser session changes. New targeted source tests are unrun.

Placement auth retirement retains the single actual request/body slot through settlement. Only the same workspace/context may coalesce; a successor refuses busy until the predecessor settles, then explicit Retry can read afresh. Repeated observed auth cycles cannot reset this accounting or publish the old reply. The existing2.5-second transport timeout remains unchanged; the adversarial eight-cycle regression is prepared, not yet run.

Early stale-context and non-success placement responses await actual unread-body cancellation before releasing that same slot. Cancellation rejection keeps the original fixed refusal; there is no queue, replacement deadline or replay. Real ReadableStream regressions hold cancellation on both stale200 and failed503 responses through eight successor auth cycles, then release it and permit a fresh read. These additional cases are source-only pending root gates.

Named native account commands accept optional trailing expectedAccountLifetime, encoded as the fixed Tauri camelCase argument. Existing callers may omit for compatibility; a selected private account facade always supplies its original canonical64hex pro_status.account_lifetime and never retries omission after failure. Status also optionally proves completion of that exact original signed-out Sign in via completed_sign_in_lifetime; this preserves a non-authorizing draft only, while the new port must capture fresh account authority. accountLifetime.test.ts exercises actual wrappers, closed argument validation and one-send refusal. Native comparison under the original operation owner remains a separately coordinated implementation/gate.

The fixed `proSettleSetupProposal` bridge carries only workspace ID, bounded shown command, closed decision and optional original account lifetime; private native admission owns the fresh GET/ETag/PUT custody. It never accepts a URL, profile or caller header. Source tests cover one send and pre-admission bounds; native/runtime acceptance remains separate.

`plan.ts` retains only the shared readable/derived projections and a signal-fenced finite subscription bridge. The selected private branding owner now retains the original ten-second lookup deadline, generation checks, visibility listener, native registration and sixty-second browser refresh lifecycle; the original behavior tests move with that owner and exercise the actual shared public projection through test-only captured aliases. Public absence/projection tests keep literal-null no-IO behavior. The new relocation is source-only pending root gates.

The shared plan projection is dormant when trusted assembly selects null: no account IPC, cookie HEAD or Pro event listener. Selected branding lookup is a fixed private entry method under the existing ten-second/generation/visibility lifecycle; the same public store serves all free/shared consumers. Account-only fixed IPC wrappers are removed after their caller census and moved private; onProChanged, project copy and mirror status wrappers remain for actual shared free/recovery callers. Their DTOs and native wire remain unchanged. New absence/controller checks are source-only pending root gates.

The shared update owner remains `workspace/update.svelte.ts` with the same App polling/listeners and explicit commands; App renders `workspace/UpdateToast.svelte` statically, as do quick open, the folder picker and agent setup (a public build has no extra loading or failure states for them).
