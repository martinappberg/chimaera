# Client transport map

The public UI runs directly on a daemon, inside the native shell, or beneath a browser gateway path. Read [the transport contract](../../../../crates/chimaera-link/PROTOCOL.md) before changing gateway behavior.

Every browser view the account serves (`/workspace/{id}/`, and `/app/{id}/`
for a cloud machine or a kept cluster job's workspace) has a **Home** link in
the existing rail header and focus-mode strip, and the daemon Home's brand mark
(`workspace/HomeNavigation.svelte`) links there too. It goes to the
same-origin account root `/`, including when the sidebar is hidden on a phone.
It carries no daemon path, host selection or wake intent; ordinary daemon and
native windows have no account Home link.

Viewing a project that runs elsewhere is passive: sockets attach without `wake=interaction`, and only a user action carries wake intent. A `suspended` placement (a sleeping cloud machine keeping ownership) is routed exactly like `owned`. A keeper may keep a sleeping cloud machine's sockets open (it marks them `X-Chimaera-Sockets: kept`; [VIEWING.md](../../../../crates/chimaera-link/VIEWING.md), "A sleeping cloud machine's sockets"; negotiated per connection). Against one, a socket opens as usual, stays open and quiet, a send or keystroke on it is simply sent (the keeper holds it, wakes the machine and delivers it once), and a later `ready` on the same socket is a reattach (chat: only the gap, no reset; terminal: like a reconnect's, read against the auth frame with the `park`/`unpark` sent since folded in, `SessionSocket.wireParked`; a hidden terminal never sends a grid). `remote_unavailable` with `reason:"reconnecting"` is a relay retrying an unreachable owner (lasting, "Reconnecting…"); without it, it ends a wake on a socket that is still kept (quiet again is kept again). `placementLabel` takes `reachable` (the view's own socket is answered or kept) so a row whose roster read fails does not read "· reconnecting" then, and `ownerIsCloud` says whether a viewed conversation runs on a cloud machine. The fallback below applies when a keeper refuses or closes those sockets without advertising that capability. A chat or terminal socket that was refused, or dropped while its owner is asleep (`worker_asleep`, or a project view's latest placement read says `suspended`) waits with no timer (`reconnect.ts` `parkUntilAwake`) instead of backing off: a send or keystroke dials it with wake intent, and `ownerAwake` (an owned placement read, a project view's events socket coming up) or the row becoming reachable (`retrySoon`) dials it passively. In a native window the daemon keeps the viewer socket open and holds the first input itself; in a browser view a send or keystroke into a dropped socket reconnects once with wake intent (never queued). Viewer chrome (terminal access strip, chat connection row) is gated on a routed row (`typeof session.placement === "object"`) or a browser view (`isBrowserGateway()`), so free users never see it. Viewport width matters only in an account-gateway browser view, and only as a starting default: at phone width (≤700 px) it starts terminals watching (`terminal/viewerMode.svelte.ts`) and opens its layout in focus mode (`App.svelte`). A plain daemon in a browser and a native window of any width keep the layout `main` gives them (free users see no change), and neither default is ever saved. The full contract is [VIEWING.md](../../../../crates/chimaera-link/VIEWING.md).

Never put browser credentials in JavaScript, storage, URLs or proxy pages. Gateway requests use an HttpOnly cookie and same-origin proof; account browser sessions are distinct from daemon bearer tokens. Host choice belongs to the URL, never a shared cookie. Keep direct/native URLs unchanged, and preserve nonsecret workspace/window bootstrap metadata when switching hosts. Arbitrary preview apps must run on their isolated preview origin; their opaque proxy ids are capabilities, never raw daemon tokens. No user-selected upstream origin is accepted by the gateway helper.

Checks: `npm --prefix web-ui run check`, targeted `base.test.ts`, and live shared-UI HTTP + terminal/event WebSocket verification through the gateway. A passing direct-daemon check alone does not exercise gateway prefixes.

Personal provider wrappers use separate `pro_personal_provider_*` IPCs with closed
original parent identity and one-shot command payloads. There is no daemon or
URL fallback; personal account transport selection belongs to the private optional account controller.

The optional kept adapter captures an opaque public API owner (no token or request method) and the exact logical placement owner. Auth loss or recovery, or a genuinely new bearer, retires old intent; an ordinary account refresh or events-socket reconnect does not, and a delayed old 401 cannot retire a recovered owner. Auth retirement invalidates pending placement publication and coalescing. The opt-in `ApiGuard` is checked before preparation, after the placement await, immediately before fetch and after the reply; guarded kept JSON decoding rechecks before delivery. A placement owner compares workspace/epoch/holder/route_host_id from the same row that fills the headers, so owned↔suspended renewal of one owner is not a change. Unguarded routes and headers are unaffected. These guards are client intent fences, not wire authority or proof of unseen browser session changes.

Placement auth retirement keeps the one in-flight request/body slot until it settles. Only the same workspace and context coalesce; a successor refuses busy until the predecessor settles, and an explicit Retry then reads afresh, so repeated auth cycles can neither reset that accounting nor publish the old reply. Early stale-context and non-success placement responses cancel their unread body before releasing the slot (a rejected cancellation keeps the original refusal). There is no queue, replacement deadline or replay, and the 2.5-second transport timeout is unchanged.

Named native account commands take an optional trailing `expectedAccountLifetime` (a fixed Tauri camelCase argument). Older callers may omit it; a selected private account facade always supplies the original 64-hex `pro_status.account_lifetime` and never retries without it after a failure. Status may also carry `completed_sign_in_lifetime`, proof that this exact signed-out Sign in completed: it preserves a draft that authorizes nothing, and the new port captures fresh account authority.

`plan.ts` keeps only the shared readable/derived projections, the synchronous `proPossible` (the one free/not-free test: a composed extension and either this computer's own native window or the account gateway; it asks nothing, so boot, listeners and every Pro entry point read it) and a signal-fenced subscription bridge. The selected private branding owner keeps the ten-second lookup deadline, generation checks, visibility listener, native registration and sixty-second browser refresh. When the trusted assembly selects null, or `proPossible()` is false, the projection is dormant: no account IPC, network probe or Pro event listener (`planAbsent.test.ts`). Account-only IPC wrappers live in the private entry; `onProChanged`, project copy and mirror status wrappers stay public for free and recovery callers, with their DTOs and native wire unchanged.

The shared update owner is `workspace/update.svelte.ts` with the same App polling/listeners and explicit commands; App renders `workspace/UpdateToast.svelte` statically, as do quick open, the folder picker and agent setup (a public build has no extra loading or failure states for them).
